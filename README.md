# DSH 备用地址 · 0.1.0

为 DeepSeek Harness 的 pi-ai 供应商设置最多两条备用 API 地址。主线发生连接故障时，插件按顺序尝试备用线路，并在后续对话中按退避间隔尝试恢复主线。

**适用版本：DeepSeek Harness 0.2.1-rc.3。** 插件依赖该版本的适配器内部入口，暂不声明兼容其他版本。

## 安装

在 DeepSeek Harness 的插件管理中安装：

```text
dsh-provider-failover@0.1.0
```

启用后打开 **设置 → 备用地址**，选择已有供应商，填写备线 1、备线 2，打开「启用」并保存。两个输入框都可以留空，但启用时至少需要一条有效地址。配置保存后会保留，重启也不丢失。

主地址由原供应商配置提供，在本页只读。备用地址必须使用 HTTPS，不能带账号、密码、查询参数或锚点，也不能与主地址或另一条备线重复。地址应包含与主线对应的 API 基础路径，例如 `https://backup.example.com/v1`。

**仅填写你信任的端点。备用端点会接收原请求的同一份 API Key、消息和工具参数。** 插件不负责跨供应商协议或模型名称转换。

## 线路尝试规则

- 正常使用主线；主线发生可切换故障后，依次尝试备线 1、备线 2。
- 某条备线成功后继续使用，同一轮的工具调用不会为了探测主线而切回。
- 主线失败后的冷却间隔依次为 **30 秒、1 分钟、2 分钟、4 分钟、5 分钟**，之后保持 5 分钟。到期后，在下一轮对话的真实请求上尝试主线；没有新轮次就不探测，也不发送后台模型请求。
- 主线恢复后立即使用。连续稳定使用至少 5 分钟、且至少成功两次请求后，才重置故障退避；短暂恢复后再次断线，沿用之前较长的冷却。
- 每条备线也独立记录冷却。备线 2 正常时，不主动探测备线 1。所有线路都在冷却时，插件返回故障给宿主原有重试，不额外发送请求。

插件只对连接/超时故障以及 HTTP 408、502、503、504 切线。认证错误、限流、无效请求、上下文超限和取消不会触发切线。已有文本、推理或工具输出后发生错误，插件不会自动重放请求。

冷却与当前线路只保存在内存中，同一适配器实例下的会话共享线路健康状态；地址表变化、插件重新加载或宿主重启会重置。保存的备用地址不受影响。

## 当前线路显示

会话标题栏显示「默认地址」「备用地址1」或「备用地址2」。尝试连接时显示「连接默认地址……」或对应的备用地址；收到服务响应后才确认当前线路。鼠标悬停、键盘聚焦或点击标签可查看具体 API 地址。

状态按会话显示，备线编号对应设置中的固定位置。状态通道断开时隐藏标签，避免将过期信息显示为当前线路。

## 请求与安全边界

插件在内存中可逆地包装活动 `PiAiAdapter.streamWithSnapshot`，只覆盖本次调用模型副本的 `baseUrl`，其余请求由原适配器发送。插件不修改持久供应商配置、模型或 API Key，不修改或替换 Desktop 的 `app.asar`；卸载时恢复原适配器方法。

目前仅支持显式 API Key 的 pi-ai 路由，辅助用途请求不切线。切线不保证备用服务可达，也不会给每条线路额外分配一套重试次数。多个并发请求不共享消息或请求对象，但共享对应供应商的内存冷却记录。

## 验证情况

本地测试覆盖退避时间、同轮粘滞、稳定恢复、错误分类、取消、部分流输出保护、配置写入及卸载恢复。未经修改的 rc3 适配器连接本地模拟服务，验证主备请求体一致，模型、参数、路径和合成密钥保持不变。

实际 Desktop 页面已由使用者确认正常渲染；在页面保存备用地址后，断网错误显示请求已尝试备用域名，重启后配置仍保留。真实备用服务成功返回不作为本次验收条件，测试未向用户端点发送探测请求。
